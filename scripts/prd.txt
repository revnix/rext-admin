# Overview  
The Topic Builder is a comprehensive AI-powered content topic generation tool that replaces the existing general business idea builder with a specialized wizard for creating content topics. This product solves the challenge content creators, marketers, and writers face when generating relevant, engaging, and targeted content ideas across different industries, audiences, and platforms.

**Target Users:**
- Content creators and writers seeking topic inspiration
- Marketing teams planning content calendars
- Educators developing curriculum topics  
- Business professionals creating thought leadership content
- Social media managers generating platform-specific content ideas

**Value Proposition:**
- Eliminates content creator's block through AI-generated topic suggestions
- Provides industry-specific and audience-targeted topic recommendations
- Offers dual-flow wizard supporting both topic-first and industry-first approaches
- Generates topics optimized for specific content formats and distribution channels
- Includes advanced scoring system for relevance, freshness, and novelty

# Core Features  

## 1. Hybrid Wizard Flow System
**What it does:** Provides two distinct user paths - Subject-First Flow (when users have specific topics in mind) and Industry-First Flow (when users start with broad industry interests)
**Why it's important:** Accommodates different user starting points and creative processes
**How it works:** 8-step progressive disclosure wizard with dynamic form dependencies and conditional field rendering

## 2. AI-Powered Topic Generation Engine  
**What it does:** Leverages OpenAI/Groq APIs to generate contextually relevant content topics based on comprehensive user inputs
**Why it's important:** Provides high-quality, creative topic suggestions that human brainstorming might miss
**How it works:** Processes form data through structured prompts, returns JSON-formatted topic arrays with metadata

## 3. Dynamic Industry-Audience Mapping
**What it does:** Automatically suggests relevant audience personas based on selected industry with smart defaults
**Why it's important:** Reduces user cognitive load while ensuring comprehensive targeting
**How it works:** Dependency system that updates audience options when industry changes, includes YMYL detection

## 4. Multi-Platform Content Optimization
**What it does:** Tailors topic suggestions for specific content formats (blog, social media, video, etc.) and platforms (YouTube, LinkedIn, etc.)
**Why it's important:** Different platforms require different content approaches and tonality
**How it works:** Conditional form fields and platform-specific prompt modifications

## 5. Advanced Topic Scoring & Filtering
**What it does:** Provides relevance, freshness, and novelty scores for each generated topic with sorting capabilities
**Why it's important:** Helps users quickly identify the most suitable topics for their needs
**How it works:** AI-generated numerical scores (0-1 scale) with client-side filtering and sorting

## 6. Topic Management & Export System
**What it does:** Allows users to save, edit, regenerate, and export selected topics in various formats
**Why it's important:** Integrates with broader content workflow and planning processes  
**How it works:** Local storage for drafts, bulk actions for topic management, export to JSON/CSV

## Key User Flows

### Flow 1: Subject-First Journey (Expert Users)
1. **Entry:** User arrives with specific topic in mind
2. **Input:** Enters primary subject/keyword 
3. **Context:** Selects industry, content type, platform
4. **Targeting:** Defines audience and demographics
5. **Goals:** Sets content purpose and tone preferences
6. **Advanced:** Optionally adds keywords, constraints, regional preferences
7. **Review:** Confirms all selections in summary view
8. **Generate:** Receives AI-generated topic suggestions with scores
9. **Action:** Saves, edits, or regenerates topics as needed

### Flow 2: Industry-First Journey (Exploratory Users)
1. **Entry:** User explores without specific topic
2. **Industry:** Selects broad industry/domain
3. **Focus:** Optionally narrows to specific subtopic area
4. **Format:** Chooses content type and distribution platform
5. **Audience:** Defines target demographics and personas
6. **Style:** Sets content goals, tone, and preferences
7. **Advanced:** Adds optional constraints and regional targeting
8. **Review:** Validates all inputs before generation
9. **Generate:** Receives diverse topic suggestions for industry
10. **Refine:** Iterates on results or explores different angles

- **Advanced Options:** Collapsible sections for keywords, constraints, regional preferences

### Visual Design Principles

- **Keyboard Navigation:** Full wizard navigation without mouse
- **Screen Reader Support:** Proper ARIA labels and landmark roles
- **Color Blind Friendly:** Non-color-dependent status indicators  
- **Mobile Responsive:** Touch-friendly interface with optimized layouts

# Technical Architecture  

## System Components

### Frontend Architecture (Next.js 15 App Router)
**Framework:** Next.js 15+ with App Router, React 19, TypeScript 5+
**UI Components:** shadcn/ui v3 + Radix UI primitives for accessibility
**Styling:** Tailwind CSS 4 with custom component library
**State Management:** 
- React useState for wizard form state with custom hooks
- TanStack Query for server state and API caching (planned for future phases)
- Zustand for global state management (if needed)

**Key Frontend Components:**
```
/app/ideas/create/page.tsx (main wizard container)
/components/topic-builder/
  ├── steps/ (individual wizard steps)
  ├── results/ (topic display and management)
  └── ui/ (specialized UI components)
/types/topic-builder.ts (TypeScript interfaces)
/hooks/use-topic-builder.ts (form state management)
```

### Backend Integration
**API Layer:** Next.js API Routes (/app/api/generate-topics/route.ts)
**AI Services Integration:**
- **Primary:** OpenAI API (gpt-4-turbo, gpt-3.5-turbo)
- **Secondary:** Groq API (Llama, Mixtral models) for cost optimization
- **Package:** `openai@^4.x` npm package for latest OpenAI integration
- **Fallback:** Structured prompt templates with retry logic

**Data Models:**

## Atomic Development Approach

### Build Strategy: Horizontal Slicing
Each feature is built as a complete horizontal slice that provides immediate value:

1. **Types First:** Complete interface definition enables parallel development
2. **Static Then Dynamic:** Static layouts first, then add interactivity
3. **Mock Then Real:** Mock APIs enable end-to-end testing before external dependencies
4. **Core Then Polish:** Essential functionality before enhancements

### Incremental Value Delivery
Each phase delivers a functional improvement:

- **Week 1:** Type-safe static wizard (no functionality, but shows progress)
- **Week 2:** Functional wizard with mock data (complete user flow testable)
- **Week 3:** Real AI integration (MVP functional)
- **Week 4:** Enhanced UX and topic management (production ready)

### Testing Integration Points
**Parallel Testing Development:**
- Unit tests written alongside each utility function
- Component tests for each wizard step as it's built
- Integration tests for form state management
- End-to-end tests using mock API first, then real API

### Risk Mitigation Through Dependencies
**Low-Risk Foundations First:**

- AI integration is isolated and can be swapped/modified without affecting UI

**High-Risk Components Last:**

# Risks and Mitigations  

## Technical Risks

### 1. AI API Reliability and Rate Limiting
**Risk:** OpenAI/Groq API downtime or rate limits could render the product unusable
**Impact:** High - Core functionality depends on AI services
**Probability:** Medium - External service dependencies always carry risk
**Mitigation Strategies:**
- Implement multiple AI provider fallbacks (OpenAI → Groq → fallback prompts)
- Build comprehensive retry logic with exponential backoff
- Create cached response system for similar prompt patterns
- Implement graceful degradation with pre-generated topic examples
- Set up monitoring and alerting for API response times and error rates

### 2. Complex Form State Management
**Risk:** Dynamic form dependencies and conditional logic could become unmaintainable
**Impact:** Medium - Could slow development and introduce bugs
**Probability:** Medium - Complex state interactions are inherently risky
**Mitigation Strategies:**
- Use TypeScript for compile-time validation of state transitions
- Implement comprehensive unit tests for all form state logic
- Create state machine pattern for form progression validation
- Build isolated component testing to catch dependency issues early
- Document all form dependencies and interaction patterns

### 3. Performance Issues with Large Option Sets
**Risk:** Large industry/audience/platform option lists could cause UI lag
**Impact:** Medium - Poor user experience, especially on mobile
**Probability:** Low-Medium - Depends on data size and implementation
**Mitigation Strategies:**
- Implement virtualization for large dropdown lists
- Use lazy loading and search-based filtering
- Optimize re-rendering with React.memo and useMemo
- Consider pagination for option sets
- Implement performance monitoring and bundle size analysis

### 4. AI-Generated Content Quality
**Risk:** Generated topics may be irrelevant, inappropriate, or low-quality
**Impact:** High - Directly affects product value proposition
**Probability:** Medium - AI output quality varies with prompt design
**Mitigation Strategies:**
- Develop comprehensive prompt engineering with multiple templates
- Implement content filtering and YMYL safety measures
- Build topic scoring system to surface best results first
- Create feedback mechanism for topic quality improvement
- Establish manual review process for YMYL industries

## Product and Scope Risks
