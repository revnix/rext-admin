# Copywriting: Voice & Tone Guidelines

When generating text, adhere to this brand persona.

## Brand Personality Keywords

* **Professional but approachable** - We're experts, but we don't talk down to users
* **Direct and efficient** - Get to the point quickly; respect user's time
* **Tech-savvy but jargon-free** - Use technical terms only when necessary and explain them
* **Empathetic** - Understand user frustrations and address them with care
* **Confident** - We know our product works; we don't need to oversell

## Voice Characteristics

### What We Sound Like
* Clear and concise
* Helpful and supportive
* Knowledgeable without being condescending
* Friendly without being overly casual

### What We Don't Sound Like
* Overly formal or corporate
* Cutesy or trying too hard to be funny
* Aggressive or pushy
* Vague or ambiguous

## Grammar & Mechanics Rules

### Headings
* **H1, H2:** Use Title Case (e.g., "Getting Started with Our Platform")
* **H3+:** Use sentence case (e.g., "How to configure your settings")

### Punctuation
* Avoid exclamation points (!) in standard interface copy
* Use periods for complete sentences
* Use commas for clarity, not decoration
* Em dashes (—) are acceptable for emphasis or asides

### Sentence Structure
* **Prefer active voice** over passive voice
  * ✅ "We updated the dashboard"
  * ❌ "The dashboard was updated"
* **Keep sentences concise** - Aim for 15-20 words per sentence
* **One idea per sentence** - Don't cram multiple concepts together

### Lists
* Use bullet points for unordered items
* Use numbered lists for sequential steps
* Keep list items parallel in structure
* End list items with periods only if they're complete sentences

## Terminology Guide

| Do Not Use | Use Instead | Reason |
|:-----------|:------------|:-------|
| "Utilize" | "Use" | Simpler and more direct |
| "In order to..." | "To..." | Unnecessary words |
| "At this point in time" | "Now" | Concise |
| "Please be advised" | "Note" or "Remember" | Less formal |
| "Leverage" | "Use" or "Take advantage of" | Overused jargon |
| "Functionality" | "Feature" or "Capability" | More user-friendly |
| "Execute" | "Run" or "Complete" | Simpler |
| "Terminate" | "End" or "Stop" | Less harsh |

## Content Types

### Error Messages

**Structure:** Problem + Solution + (Optional) Next Step

✅ **Good:**
```
Unable to save changes. Check your internet connection and try again.
```

❌ **Bad:**
```
ERROR 500: Internal server exception occurred during transaction processing.
```

**Rules:**
* Never blame the user
* Always provide a solution or next step
* Avoid technical error codes in user-facing messages
* Use plain language

### Success Messages

**Structure:** Confirmation + (Optional) Next Step

✅ **Good:**
```
Settings saved. Your changes will take effect immediately.
```

❌ **Bad:**
```
Success! Your settings have been successfully saved to the database!
```

**Rules:**
* Be brief and clear
* Avoid redundancy ("successfully saved" → "saved")
* Suggest logical next steps when appropriate

### Button Labels

**Rules:**
* Use action verbs (Save, Delete, Cancel, Continue)
* Be specific ("Delete Account" not just "Delete")
* Keep it short (1-3 words ideal)
* Use sentence case

✅ **Good:** "Save changes", "Create account", "Learn more"
❌ **Bad:** "Click here", "Submit", "OK"

### Form Labels

**Rules:**
* Use clear, descriptive labels
* Place labels above input fields
* Mark required fields with asterisk (*)
* Provide helpful placeholder text when needed

✅ **Good:**
```
Email address *
example@company.com
```

❌ **Bad:**
```
Enter your email here
```

### Help Text & Tooltips

**Rules:**
* Keep it under 100 characters
* Explain the "why" not just the "what"
* Use when the label alone isn't clear enough

✅ **Good:**
```
Two-factor authentication adds an extra layer of security by requiring a code from your phone.
```

❌ **Bad:**
```
2FA is a security feature.
```

## Tone Variations by Context

### Marketing Copy
* **Tone:** Confident, inspiring, benefit-focused
* **Length:** Flexible, but respect user attention
* **Goal:** Communicate value clearly

### Documentation
* **Tone:** Instructional, patient, thorough
* **Length:** As long as needed for clarity
* **Goal:** Enable user success

### Interface Copy (Buttons, Labels, Menus)
* **Tone:** Direct, action-oriented, minimal
* **Length:** As short as possible
* **Goal:** Guide user actions efficiently

### Error/Warning Messages
* **Tone:** Helpful, calm, solution-focused
* **Length:** Brief but complete
* **Goal:** Resolve user's issue quickly

## Writing Checklist

Before finalizing any copy:

- [ ] Is it clear and easy to understand?
- [ ] Does it match our brand personality?
- [ ] Is it free of jargon (or is jargon explained)?
- [ ] Does it use active voice?
- [ ] Are sentences concise (15-20 words)?
- [ ] Does it follow our terminology guide?
- [ ] Is punctuation correct per our rules?
- [ ] Does it provide value to the user?
- [ ] Would I want to read this?

## Examples

### Before & After

**Before:**
```
In order to utilize the advanced functionality of our platform, users are required to 
execute the configuration process which can be accessed via the settings panel.
```

**After:**
```
To use advanced features, configure your settings in the Settings panel.
```

**Before:**
```
ERROR: Authentication failure detected. Please be advised that your credentials are invalid.
```

**After:**
```
Unable to sign in. Check your email and password, then try again.
```

---

**Remember**: Good copy is invisible. Users should understand immediately without having to think about it.
